# Sanity Metadata Update Runbook

This runbook applies the first reviewed metadata batch from `docs/seo-migration/metadata-inventory.md`.

## Scope

The script only prepares or applies P0/P1 SEO field updates for:

- `siteSettings.defaultSeoTitle`
- `siteSettings.defaultSeoDescription`
- eight `industry.seoTitle` / `industry.seoDescription` pairs
- eight P1 `blogPost.seoTitle` / `blogPost.seoDescription` pairs
- `caseStudy.seoDescription` for `virtual-tours-ai-listings`, guarded by the current thin description

It does not update services, P2/P3 blog posts, P2 case studies, `defaultOgImage`, slugs, canonicals, redirects, robots/noindex behavior, schema, or page content.

## Required Environment Variables

For dry-run:

```bash
PUBLIC_SANITY_PROJECT_ID=5rux0mv2
PUBLIC_SANITY_DATASET=production
```

For apply:

```bash
PUBLIC_SANITY_PROJECT_ID=5rux0mv2
PUBLIC_SANITY_DATASET=production
SANITY_WRITE_TOKEN=<token with write access to the production dataset>
```

The apply path refuses to run unless `SANITY_WRITE_TOKEN` is present and the resolved Sanity target is exactly `5rux0mv2` / `production`.

## Dry Run

Dry-run is the default and does not write to Sanity:

```bash
node scripts/sanity/update-seo-metadata.mjs
```

Equivalent explicit command:

```bash
node scripts/sanity/update-seo-metadata.mjs --dry-run
```

Review every row. The output prints document type, slug or singleton title, current value, proposed value, and whether the field would be changed. A field is changed only when the current value matches the guard in `scripts/sanity/seo-metadata-batch-1.json`.

## Apply

After reviewing the dry-run output:

```bash
node scripts/sanity/update-seo-metadata.mjs --apply
```

The apply run aborts if any targeted document is missing or any current field no longer matches its inventory guard. This prevents overwriting metadata that may have been edited manually after the inventory was created.

## Rollback Approach

Before applying, save the dry-run output because it includes the previous value for every field. If rollback is needed:

- Use Sanity document history to restore the affected `siteSettings`, `industry`, `blogPost`, or `caseStudy` documents.
- Or run a reviewed reverse patch that restores each field to the `Current` value printed in the dry-run/apply output.
- For fields that were previously empty, rollback means unsetting or clearing the corresponding `seoTitle` / `seoDescription` field.

Do not roll back by changing slugs, redirects, canonicals, robots/noindex behavior, schema, or body content.

## Built-Site Verification

After apply, rebuild the site:

```bash
npm run build
```

Then inspect generated metadata in `dist/client`. Examples:

```bash
rg -n "<title>|name=\"description\"|property=\"og:title\"|property=\"og:description\"" dist/client/industries/healthcare/index.html
rg -n "<title>|name=\"description\"|property=\"og:title\"|property=\"og:description\"" dist/client/insights/cloud-deployment-models-diagram/index.html
rg -n "<title>|name=\"description\"|property=\"og:title\"|property=\"og:description\"" dist/client/work/virtual-tours-ai-listings/index.html
```

Expected result: title, meta description, Open Graph title, and Open Graph description reflect the Sanity SEO fields from the batch. Canonical URLs and non-production noindex behavior should remain generated by the existing layout code.
