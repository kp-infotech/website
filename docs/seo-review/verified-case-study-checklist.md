# Verified case study publication checklist

**Complete in approved private storage. This public file is a blank checklist, not evidence or approval.** Keep raw evidence, confidential identities and completed review dossiers outside public Sanity and Git. The public repository may contain only opaque reference IDs, statuses, approved public wording and non-confidential methodology. CMS governance fields contain statuses only.

- [ ] Actual engagement verified from an authoritative source.
- [ ] KP's delivery scope verified; distinguish KP work from client/vendor work.
- [ ] Named public client or anonymized descriptor explicitly approved.
- [ ] Publication permission approved for the exact wording, channel and assets.
- [ ] Project/delivery year separately supported if shown; CMS timestamps are not delivery evidence.
- [ ] Technical implementation assertions supported by delivery artifacts and acceptance.
- [ ] Every metric independently sourced, with definition, baseline, comparison period, numerator/denominator, source and calculation recorded privately.
- [ ] Attribution limits, normalization, exclusions and measurement limitations documented.
- [ ] Each result entry marked approved only after its private review; summary outcomes reviewed separately.
- [ ] Testimonial original attributable source, identity/role and exact quote wording approval confirmed.
- [ ] Portrait/image permission confirmed when shown; screenshots and other assets approved and free of confidential data.
- [ ] Certification, partner, compliance and award claims independently verified for exact legal entity, issuer/provider, scope and current status/date.
- [ ] Funding claims checked against an authoritative source, exact entity, round, amount and period.
- [ ] Titles, excerpts, cards, metadata and social descriptions reviewed against approved wording.
- [ ] CreativeWork and other schema reviewed; no invented Review, AggregateRating, award or attestation.
- [ ] Service relationships remain technically relevant; AI features are not action-taking-agent proof.
- [ ] Re-review owner and source-defined expiry/event triggers recorded privately.
- [ ] No confidential information leaked through copy, images, alt text, metadata, schema, CMS fields or Git artifacts.
- [ ] Evidence status set to `verified` and publication permission to `approved` only after this review.
- [ ] `publicProofType` set to `verifiedCaseStudy`; per-result, date, summary and testimonial markers set only for approved items.
- [ ] Build input/output gates and SEO regressions pass. Changes to the current five-page Step 9B baseline require deliberate review of approved new wording and regression fixtures; never weaken tests simply to restore prohibited claims.

Do not promote a page on topical relevance, old publication, repetition, CMS presence or an unsupported owner assertion alone. Missing evidence leaves a Technical Overview, not a verified engagement.
